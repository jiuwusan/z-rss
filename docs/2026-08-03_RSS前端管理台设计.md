# RSS 前端管理台设计

## 目标

使用原生 HTML、CSS、JavaScript 为现有 RSS 后端提供同源单页管理台。页面由 Koa 在 `/` 提供，不引入前端框架、构建工具、外部字体或图标资源。

## 页面范围

- 查看订阅平台列表。
- 新增平台、修改 RSS 地址、删除平台。
- 手动刷新全部平台缓存并展示分平台结果。
- 展示平台数、缓存条目数和本次刷新时间。
- 按后端顺序展示全部聚合条目。
- 打开资源链接、查看和复制原始 item XML。
- 提供加载、空数据、错误、操作成功和危险操作确认反馈。

## 视觉与布局

采用桌面优先的响应式管理台：

- 顶部为品牌标题、服务状态和“刷新全部缓存”主按钮。
- 下方三张概览卡展示平台数、缓存条目数和最近刷新时间。
- 主区域左侧为订阅平台管理卡，右侧为占主要宽度的条目流。
- 条目使用紧凑卡片，突出标题、平台和发布时间，操作按钮保持次要层级。
- 新增/编辑平台和查看 XML 使用原生 `dialog`，移动端改为近全屏布局。
- 使用浅色暖灰背景、深色文字和青绿色强调色，不依赖远程视觉资源。

## 文件结构

```text
backend/
├── public/
│   ├── index.html
│   ├── styles.css
│   └── app.js
├── src/app.js
├── Dockerfile
└── tests/frontend.test.js
```

`koa-static` 负责提供 `public/`。中间件顺序为错误处理、JSON body parser、静态文件、API 路由、404，API 行为保持不变。

## 数据流

1. 页面加载时并行请求 `GET /rss/platforms` 与 `GET /rss/items`。
2. 平台新增、修改或删除成功后刷新平台列表；删除后同时刷新条目列表。
3. 点击刷新时调用 `POST /rss/cache/refresh`，展示成功/失败数量与各平台状态，再读取最新条目。
4. 聚合列表只展示后端缓存，不在浏览器中请求 RSS 地址。
5. 所有接口错误统一显示 toast，并保留页面上一次成功数据。

## 交互规则

- `platform` 新增时可编辑，修改时固定为原平台名，只允许更新 `rss`。
- 删除前使用确认框，提示会同步删除对应缓存。
- 操作执行期间禁用相关按钮，避免重复提交。
- 条目 title 为空时显示“未命名条目”，无效日期显示“时间未知”。
- 原始 XML 使用 `textContent` 放入 `<pre>`，避免执行其中的 HTML。
- 外部链接使用 `target="_blank" rel="noopener noreferrer"`。

## 错误与安全

- API 非成功响应优先展示后端 `message`，无法解析时使用通用错误文案。
- 动态内容使用 DOM `textContent`，不把 RSS title、link、xml 拼入不可信 HTML。
- 页面不增加认证能力，继续遵循后端 README 的可信网络部署边界。
- 删除、刷新和保存失败不会清空现有页面数据。

## 测试与验收

- HTTP 测试验证 `/`、`/styles.css`、`/app.js` 可访问且 Content-Type 正确。
- 静态页面测试验证核心区域、对话框、无障碍状态区域和模块脚本引用存在。
- JavaScript 单元测试验证日期格式化、刷新摘要和缺省标题等纯函数。
- 原有 31 个后端测试继续通过。
- 实际启动服务后验证页面资源、平台接口和条目接口均返回 200。
- Dockerfile 必须复制 `public/`，确保容器内可访问页面。

## 未包含

- 前端路由、分页、搜索、主题切换、用户认证和权限管理。
- 框架、打包、TypeScript、CSS 预处理器或远程 CDN。
- 浏览器直接访问外部 RSS。
