# Koa 后端初始化设计

## 目标

在空的 `backend/` 目录中初始化一个基于 Koa 的最小可运行后端工程，采用 ES Modules，并按经典技术层组织代码。首版提供健康检查、统一响应、404 处理、异常处理、环境配置、基础测试和使用说明。

## 范围

### 本次包含

- Koa 应用创建与 HTTP 服务启动。
- `route → controller → service → util` 分层示例。
- `GET /health` 健康检查接口。
- 统一成功响应、404 响应和异常响应。
- 基于环境变量的端口与运行环境配置。
- Node.js 内置测试运行器与 Supertest 接口测试。
- 开发、生产启动脚本和后端 README。

### 本次不包含

- 数据库及 ORM。
- 用户认证与权限控制。
- 业务日志框架。
- 请求参数校验框架。
- 自定义业务错误类。
- 与 RSS 业务相关的接口。

## 技术选择

- 模块规范：ES Modules（`import/export`）。
- 包管理器：npm。
- Web 框架：Koa。
- 路由：`@koa/router`。
- 环境变量：`dotenv`。
- 测试：Node.js 内置 `node:test` 与 `supertest`。

优先使用当前 Node.js LTS，依赖版本以安装时生成的 `package-lock.json` 为准。

## 模块职责

- `app.js`：创建 Koa 实例，按顺序注册错误处理与路由，不监听端口。
- `server.js`：读取应用配置，启动 HTTP 服务并监听端口。
- `config/`：集中读取和规范化环境变量，提供默认配置。
- `routes/`：声明 HTTP 方法与路径，并将请求映射至 Controller。
- `controllers/`：处理 Koa 上下文，调用 Service，通过响应工具设置结果。
- `services/`：承载业务逻辑，不依赖 Koa 的 `ctx`。
- `middlewares/`：承载跨请求处理逻辑，首版仅实现统一异常处理。
- `utils/`：放置无状态通用方法，首版提供统一响应构造方法。

依赖方向固定为 `route → controller → service → util`。下层模块不得反向依赖路由或 Controller。

## 请求处理流程

`GET /health` 的处理过程如下：

1. Router 匹配 `GET /health`。
2. Controller 调用健康检查 Service。
3. Service 返回 `status`、`timestamp`、`uptime`。
4. Controller 使用响应工具写入统一成功响应。

成功响应为：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "ok",
    "timestamp": "2026-08-02T00:00:00.000Z",
    "uptime": 1.23
  }
}
```

其中 `timestamp` 使用 ISO 8601 字符串，`uptime` 使用 Node.js 进程运行秒数。

## 404 与异常处理

路由未匹配时返回 HTTP `404`：

```json
{
  "code": 404,
  "message": "接口不存在",
  "data": null
}
```

错误处理中间件注册在最外层，捕获下游同步和异步异常：

- 使用异常携带的合法 HTTP 状态码；未知异常使用 `500`。
- HTTP `500` 固定返回“服务器内部错误”。
- 非 500 异常可使用异常消息作为对外提示。
- 响应体遵循 `{ code, message, data }`，错误时 `data` 为 `null`。
- 响应中不包含堆栈或内部异常对象。
- 开发环境允许在服务端控制台记录异常，不改变响应结构。

首版不引入自定义错误类。

## 配置与运行

配置项：

- `PORT`：监听端口，默认 `3000`。
- `NODE_ENV`：运行环境，默认 `development`。

`.env.example` 提供上述变量示例，真实 `.env` 不提交仓库。

npm 脚本：

- `npm start`：执行 `node src/server.js`。
- `npm run dev`：执行 `node --watch src/server.js`。
- `npm test`：执行 Node.js 内置测试运行器。

## 测试设计

测试直接使用 `app.callback()`，不启动固定端口：

- 健康检查测试：断言 HTTP `200`、统一成功结构、`status` 为 `ok`，并校验时间戳与运行时长的类型。
- 404 测试：访问未知路径，断言 HTTP `404` 和固定错误结构。
- 错误中间件测试：构造抛出未知异常的下游处理，断言转换为 HTTP `500`，且响应体不包含堆栈和原始异常消息。

实现遵循测试驱动流程：先编写并运行失败测试，再添加最小实现使测试通过，最后运行全部测试。

## 验收标准

- 在 `backend/` 执行 `npm install` 后可生成一致的依赖锁文件。
- `npm start` 能启动服务，默认监听 `3000` 端口。
- `GET /health` 返回设计约定的成功响应。
- 未知路径返回设计约定的 404 响应。
- 未知异常被转换为安全的 500 响应。
- `npm test` 全部通过。
- README 清楚说明目录职责、环境配置、启动和测试命令。
