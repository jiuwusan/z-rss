# RSS 最终评审修复实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development and superpowers:verification-before-completion to implement this plan task-by-task.

**目标：** 修复 RSS 原始 item 提取与非 2xx 响应体释放问题，并明确接口的认证/SSRF 部署边界。

**架构：** 保留 `fast-xml-parser` 的 XML 合法性校验与字段解析，只用一个不构造新 XML 的词法扫描器定位 RSS `channel` 的直接 `item` 子元素，从源文本按索引截取原文。刷新服务在平台级非 2xx 分支中等待响应体取消，取消失败仍返回原有平台失败结果。

**技术栈：** Node.js 22、ES Modules、`node:test`、`fast-xml-parser`、WHATWG `Response`/`ReadableStream`。

## 全局约束

- 不新增认证、授权或 URL/SSRF 拦截行为。
- 不新增响应大小限制，不重构 JSON 双文件存储事务。
- 保留既有服务接口、平台级失败语义及并发互斥修复。
- 生产行为必须先看到对应回归测试按预期失败，再做最小实现。
- 所有修复合并为一个 commit，不 push，不提交 `sessions/session_2026-08-03.md`。
